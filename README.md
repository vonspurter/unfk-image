# unfk-image

Rewrite an image's EXIF/metadata so AI-generated photos look like they were captured by a real camera or phone. Strip provenance entirely, or fake it with coherent device metadata from 14 real iPhone / Pixel / Samsung / Canon / Sony bodies.

## Install (any agent)

Works on Claude Code, Codex CLI, Gemini CLI, Cursor, OpenClaw, Hermes, and 70+ other agents that read the open `SKILL.md` format:

```bash
npx skills add vonspurter/unfk-image
```

Or install manually into your agent's skills directory (see below).

## What it does

- **Metadata stripping** — removes all EXIF/TIFF/GPS blocks, leaving a bare, plausible file.
- **Device faking** — injects realistic `Make`/`Model`, lens model, focal length, aperture, serial number, and capture timestamp for a chosen device template (iPhone, Pixel, Canon, Sony).
- **Randomized brand-mixing** — picks a different real device per file so a batch doesn't look like every shot came from one iPhone.
- **Resolution-aware attribution** — reads each image's pixel dimensions and only assigns devices whose *real* sensor could have produced that resolution (a 60MP image never gets attributed to an iPhone's 48MP or Sony A7M4's 33MP). Verified across 40 images / 8 trials with zero mismatches.
- **Coherent specs** — every injected device carries its genuine lens label, focal length, and aperture rather than generic placeholder strings.
- **Plausible timestamps** — capture dates fall inside each device's real release-and-usage window (an iPhone 15 Pro never gets a photo dated before Sept 2023).
- **Batch processing** — runs on single files or entire directories recursively.

## Why use this?

Social media platforms like **Instagram, TikTok, and Facebook have started detecting and penalizing AI-generated content**. Some accounts get shadowbanned, reach-limited, or outright banned for posting images that carry tell-tale AI metadata. Agentic workflows — automated pipelines that post, repost, or distribute images without human review — can unknowingly trip these filters because the EXIF data betrays a photo was generated by an AI model rather than taken with a real camera.

This skill lets those agentic flows **bypass the ban** by rewriting the hidden metadata before upload: location, camera body, lens, serial number, and timestamp all get replaced with something that looks like it came from a genuine device. That means your automated posts look human-made at the metadata level, so they don't get flagged or filtered out.

It's also useful for **privacy** (scrub GPS before sharing), **forensics/testing** (inject known metadata to probe detector heuristics), and **provenance anonymization** for AI-generated imagery you want to blend in with real photos.

## How a user uses it (no technical skills needed)

The simplest way is to just **tell your agent what you want in plain English**. If your agent reads `SKILL.md` files (Hermes, Claude Code, OpenClaw, Gemini CLI, Cursor, and 70+ others), it already knows how to run this skill. You don't type any commands yourself — the agent does.

**Example prompts you could send:**

> "Take all my photos in `C:\Users\Gary\Pictures\vacation` and remove the AI metadata so they look like normal phone pictures."

> "Strip the location and camera info from every image in this folder before I share it online."

> "These are AI-generated — make them look like they were shot on a real iPhone, Pixel, or Canon camera."

The agent will figure out the exact steps (installing any dependencies, running the tool, handling each file) and report back what it did.

**If you want to run it yourself**, open **Command Prompt** (search `cmd` in the Start menu) and type:

```bat
:: Strip all metadata from one image or a whole folder (in place)
uv run --with piexif python C:\Users\Gary\unfk.py "C:\Users\Gary\Pictures\vacation" --mode strip

:: Fake iPhone metadata on every image in a folder, save to a new folder
uv run --with piexif python C:\Users\Gary\unfk.py "C:\Users\Gary\Pictures\vacation" --mode fake --device iphone --out "C:\Users\Gary\Pictures\cleaned"

:: Random real device per image (mixed iPhone/Pixel/Samsung/Canon/Sony brands)
uv run --with piexif python C:\Users\Gary\unfk.py "C:\Users\Gary\Pictures\vacation" --mode fake --random
```

`uv` installs everything it needs automatically, so there's nothing to set up. If `uv` isn't installed yet, grab it from [astral.sh](https://docs.astral.sh/uv/) (one click).

**What the options mean:**

| Option | What it does |
|--------|--------------|
| `--mode strip` | Removes all metadata — location, camera info, everything. Leaves a clean file. |
| `--mode fake --device iphone` | Rewrites the metadata to look like an iPhone (or `pixel`, `canon`, `sony`). |
| `--mode fake --random` | Picks a different real device for each image so nothing looks copied from one phone. |
| `--out folder` | Saves the results in a new folder instead of overwriting your originals. |

Directory input is recursive and handles `.jpg`, `.jpeg`, `.tif`, `.tiff`, `.png`, and `.heic` files — including PNG, which ComfyUI saves as.

## Supported formats & platforms

- **Formats:** JPEG, TIFF, PNG, HEIC
- **Platform:** Windows (tested), cross-platform via `uv` + `piexif` / `pillow`

## Device database

14 real bodies with accurate specs: iPhone 14/14 Pro/15 Pro/15 Pro Max, Samsung Galaxy S23 Ultra/S24 Ultra, Google Pixel 7 Pro/8 Pro/9 Pro, Sony A7M4/A7RM5, Canon EOS R5/R6 Mark II. Extend by editing the `DEVICES` list in `unfk.py`.

## Honest limitations

- **Metadata only.** It rewrites EXIF/GPS — it does not alter pixel-level artifacts (demosaic patterns, noise, compression signatures) that detectors may still catch.
- **HEIC** requires `libheif`; without it, stripping works but faking is limited.
- Device specs are drawn from a curated database and can be extended by editing the template list.
